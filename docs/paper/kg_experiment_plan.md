# 情感知識圖譜（L3）為論文重心 — 實驗規劃

> 論文重心改為：**L3 情感知識圖譜引導的 Opus 可控生成**，
> 並加入新想法：**用官方無標籤文本當風格種子**。
> 本文件先做誠實診斷，再給出能真正撐起這個主張的實驗設計。

---

## ⚠️ 診斷：目前圖譜的證據強度是零，而且實作上「圖」沒有在做事

在規劃新實驗前，必須先面對四個問題。前兩個是**實作問題**，不修的話論文的核心宣稱會被審稿人一眼看穿。

### 問題 1（最嚴重）：生成路徑完全沒有用到圖的邊

`affective_graph.py` 的 `seeds_for_target()`：

```python
for w, d in G.nodes(data=True):          # 只走節點
    if a_range and not (a_range[0] <= d["arousal"] <= a_range[1]): continue
out.sort(key=lambda x: -x[2]); return out[:n]
```

- 只用 **VA 區間過濾節點**，`G[w]`（邊）一次都沒碰。
- kNN 邊只在 `propagate_va()` 用到，而該函式**從未被 pipeline 呼叫**（只出現在 `_demo()`）。
- ⇒ **目前的「情感知識圖譜」在生成路徑上，等價於對 CVAW/CVAP 做一次 VA 區間查表。**
  論文若宣稱「知識圖譜帶來增益」，等於宣稱了一件程式碼裡不存在的事。

### 問題 2：每個 bin 的 80 篇共用同一組固定種子詞

`seeds_for_target()` 是 `sort` 後取 `[:n]`，**決定性**、無取樣。
所以某個 bin 的 80 篇文章，看到的是**完全相同的 15 個詞**。
這既浪費了圖的結構，也是合成資料多樣性不足的直接來源。

### 問題 3：從來沒有對照組
沒有任何實驗比較過「圖譜引導 vs 隨機選詞 vs 不給種子詞」。
目前 A_PCC 0.426→0.461 的增益，**無法歸因給圖譜**——可能只是「多了 400 篇目標域風格文本」的效果。

### 問題 4：增強路線從來沒在 test set 上測過
實驗 5 / 5b / E13 / E20 全部只有 validation 分數。
而 E4 vs E19 的經驗已經證明：**val 上的排序可能是反的**。

---

## 🔧 第一步：讓「圖」真的做事（三個實作升級，建議至少做 G1+G3）

### G1. 圖擴散取種子（graph expansion）
從目標 VA 區間取**少數 anchor 詞**（3–5 個），沿 kNN 邊做 1–2 跳擴散，
把語意鄰居納入種子集，再用 VA 區間做軟過濾。

- **與現況的差別**：現況是「全詞典中 arousal 最高的 15 個詞」——那是一個語意上東拼西湊的集合
  （可能同時有「狂喜」「怒吼」「地震」）。圖擴散給的是**語意連貫**的種子群。
- **論文論點**：情緒強度對了不代表語意連貫；圖結構提供的是後者。

### G2. 標籤傳播補 OOV（讓圖涵蓋詞典沒有的詞）
`propagate_va()` + L2 FastText → 對 CVAW/CVAP 以外的詞估 VA，
特別是**新住民語域專屬詞**（居留證、仲介、婆家、匯款、口音…），這些詞詞典裡沒有。

- **論文論點**：詞典的覆蓋率是天花板，圖 + 詞向量把天花板打開。
- 這是唯一能論證「為什麼需要 L2」的實驗（否則 L2 那 814MB 在論文裡沒有位置）。

### G3. 每篇文用不同的圖鄰域（多樣性取樣）
對每次生成呼叫，隨機挑不同 anchor → 擴散 → 得到不同種子集。

- **論文論點**：可控生成的瓶頸是多樣性；圖的鄰域結構提供了**有結構的隨機性**
  （不是純隨機抽詞，而是在語意連貫的前提下換主題）。
- 附帶好處：直接改善去重保留率（現況 jieba Jaccard>0.5 會砍掉不少）。

## 💡 第二步：用官方無標籤文本當風格種子（你的想法，方向正確）

### 為什麼這個想法正好打中要害

實驗 5b 的診斷是：**A_PCC 的增益來自文本、A_MAE 的傷害來自合成文本的風格/校準偏移**
（收縮標籤救不回 → 問題不在標籤，在文本本身不像目標域）。

**用真實目標域文本當 style exemplar，直接治的就是這個病。** 這是目前所有嘗試裡，
第一個對準「已診斷出的病因」的處方。

### 可用的素材比你想的多

| 來源 | 篇數 | 標籤 |
|---|---|---|
| `DSANIDF_ValidationSet.csv` | 200 | 無 |
| `DSANIDF_TestSet.csv` | **1,100** | 無 |
| **合計** | **1,300** | 無 |

test set 的 1,100 篇也是官方發的無標籤文本，**同樣可以拿來當風格種子**。
素材量是只用 validation 的 6.5 倍。

### 合法性（論文必須寫清楚）
這是 **transductive / unlabelled-data 使用**：我們只用官方公開的**文本**，
**沒有使用任何標籤**（官方也沒發標籤）。這在 shared task 是標準做法，
但論文要明確聲明「僅使用無標籤文本作為風格範例，未使用任何測試標籤」。

### 現成的接口
`affective_graph.py` 的 `build_generation_prompt()` **已經有 `retrieved_examples` 參數**，
但 `augment_generate.py` 實際用的 `build_prompt()` **沒有這個欄位**——
也就是說接口設計時想過，但沒接上。要做的就是把它接起來。

## 🎯 第三步：把兩者接起來 —— 這才是有創新點的方法

```
L3 圖譜（情緒控制器）          官方無標籤文本（風格錨）
      │                              │
      │ 目標 VA 區間 → anchor         │
      │ → kNN 擴散 → 種子詞群          │
      │                              │
      └──── 用種子詞檢索最相關的 ──────┘
                真實文本
                    │
                    ▼
         Opus 生成：情緒區間受控 × 語域風格錨定
```

**兩個元件各司其職、且可各自消融**：
- 圖譜負責「**寫哪一種情緒**」（補 arousal 分布的洞）
- 真實文本負責「**用什麼口吻寫**」（消除風格偏移，治 A_MAE）

這個分工本身就是論文的 method 敘事，而且乾淨到可以畫成一張圖。

## 📊 核心消融矩陣（論文的主表）

| | 無真實文本錨定 | **有無標籤文本錨定** |
|---|---|---|
| **(A) 隨機詞典抽詞** | A | B |
| **(C) VA 區間查表**（= 現況實驗 5） | C ← 已有 | D |
| **(E) 圖擴散種子**（G1+G3） | E | **F ← 新方法** |
| **(N) 完全不給種子詞**（只給情緒描述） | N | — |

**必跑的格子與各自回答的問題**：

| 對照 | 回答什麼 | 優先 |
|---|---|---|
| **N vs A** | 種子詞到底有沒有用？（也許 Opus 光看「高喚醒」描述就夠了） | 🔴 |
| **A vs C** | VA 區間過濾有沒有用？（vs 隨機抽情緒詞） | 🔴 |
| **C vs E** | **圖結構有沒有用？**（vs 單純查表）← **論文的核心宣稱** | 🔴🔴 |
| **C vs D** | 真實文本錨定有沒有用？ | 🔴 |
| **E vs F** | 兩個元件是否互補（有無交互作用） | 🟠 |

> **最低限度**：N / A / C / E / F 五格。C 已經有了（實驗 5），所以要新生成四批資料。
> 若預算緊，砍掉 B 與 D，改用 **C vs E**（證圖譜）+ **E vs F**（證錨定）兩條線。

## 🔬 評估設計 —— 這一節決定實驗做完能不能下結論

**這是最容易做錯的地方。** 我們要偵測的效果量約 0.02–0.05 A_PCC，
而 test set（n=1,100）單次量測的 A_PCC 95% CI 寬度是 **0.103**。
**單次提交比不出這種差距**——這正是 E4/E19 翻車的原因，不能再犯第二次。

### 正確做法：每個條件跑 3 個 seed，用 mean ± std 比較

```bash
for cond in N A C E F; do
  for s in 42 1 2; do
    python train_v2.py --extra_train data/train_aug_${cond}.csv \
        --seed $s --run_name aug_${cond}_s$s
  done
done
```

- 每個 run 都提交 test（**每天 10 次額度，5 條件 × 3 seed = 15 次 = 兩天**）。
- 比較的是**條件間的 mean 差距 vs 條件內的 seed std**。
- 這樣才有資格說「E 比 C 好」，而不是又一次把噪聲當訊號。

> **為什麼配對比較可行**：所有條件在**同一個 test set** 上評分，噪聲高度相關，
> 因此條件間差異的變異遠小於各自 CI 所暗示的。用 seed 重複量出 within-condition 變異，
> 就能判定 between-condition 差距是否真實。**論文一定要報 mean ± std，不要報單次分數。**

### 同時要報的診斷指標（不需額外提交，本機就能算）
- 合成文本的 **arousal 分布覆蓋度**（各 bin 實際涵蓋範圍）
- **去重後保留率**（多樣性的直接代理，G3 應該要改善這個）
- **種子詞的語意連貫度**（如種子集內的平均 pairwise 相似度）— 直接量測 G1 的作用
- 訓練後模型在 test 上的 **arousal 預測 std**（是否解除壓縮）

## 📝 論文結構調整

重心換到圖譜後，原本的 selection-overfitting 分析**不要丟掉**，但改變它的角色：

- **原本**：論文的主結論（C3）
- **現在**：放在 Experimental Setup / Analysis，用來**證成本論文的實驗設計**——
  「我們在 shared task 期間吃過小驗證集選模的虧（E4/E19 排序翻轉），
  因此本文所有增強實驗一律採用 3 seed × test set 評估並報告變異。」

這個轉換其實讓論文更好：**方法論教訓變成了方法論嚴謹性的動機**，
而不是一個孤立的負面結果。審稿人會看到一支知道自己在幹嘛的隊伍。

新的貢獻列表：
- **C1**：情感知識圖譜引導的可控生成，用於補 low-resource 維度情緒任務的 arousal 分布缺口
- **C2**：以官方無標籤文本作風格錨定，解決合成資料的語域偏移（實驗 5b 診斷的病因）
- **C3**：完整消融證明圖結構與風格錨定各自的貢獻
- **C4**：（次要）小驗證集上的 arousal 模型選擇不可靠，我們有 val→test 排序反轉的直接證據

## ✅ 建議執行順序

```
第 1 步  改 affective_graph.py：G1 圖擴散 + G3 多樣性取樣（本機，無 API 成本）
         → 用 --dry_run 檢查種子詞集是否真的變得語意連貫且多樣
第 2 步  改 augment_generate.py：接上 retrieved_examples，從 1,300 篇無標籤文本檢索
         → --dry_run 檢查 prompt
第 3 步  生成 4 批資料（N / A / E / F），各 400 篇（你的終端機，計費）
第 4 步  15 個 run 上 Colab（約 4 小時）
第 5 步  兩天內提交 15 次，收集 test 分數
第 6 步  寫論文
```

**第 1、2 步沒有任何成本，而且是整個計畫的前提**（圖不做事，後面全白做）。
建議先做完這兩步、用 `--dry_run` 看種子詞和 prompt 確實變了，再花錢生成。
